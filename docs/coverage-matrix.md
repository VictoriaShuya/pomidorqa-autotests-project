# Матрица покрытия PomidorQA

Покрытие считается по функциональным требованиям MVP из [`requirements.md`](../requirements.md),
а не по числу файлов и не по строкам кода продукта. Playwright тестирует PomidorQA как
чёрный ящик: исходников приложения в репозитории нет, code coverage продукта измерить нечем.

Каждое требование получает один статус. К четырём статусам из методики курса добавлен
пятый — иначе непокрытые, но проверяемые требования пришлось бы маскировать под
`out of scope` или выдуманный `automated`.

| Статус | Что означает |
|---|---|
| `automated` | есть автотест, который падает, если поведение сломается |
| `partial` | покрыта наблюдаемая часть правила; вторая сторона (хост/сервер/негатив) — нет |
| `known defect` | требование не выполняется продуктом; тест с `test.fail()` (в наборе пока нет) |
| `out of scope` | состояние через интерфейс недостижимо, black-box проверить нечем |
| `not covered` | требование проверяемо, но теста нет |

Срез: **24.09.2026**, ветка `hw-16`, стенд `https://aiqa.su/pomidorqa`.
Методика: статусы выставлены по коду и assert’ам, не по README.

отмена за час до звонка).

## Требования и тесты

| R3.2 | Гость открывает страницу участника и видит свободные слоты | `not covered` | — |
| R3.3 | Гость не может забронировать звонок | `not covered` | — |
| R3.4 | Приватные страницы гостю недоступны | `not covered` | — |
| R3.5 | Участник редактирует профиль и навыки | `automated` | `e2e/profile-flow` |
| R3.6 | Участник добавляет и удаляет свои слоты | `partial` | `e2e/booking-flow`, helpers |
| R3.7 | Участник бронирует слоты других | `automated` | `e2e/booking-flow`, `api/booking-api` |
| R3.8 | Отменить бронирование может и хост, и гость | `partial` | `e2e/booking-cancel` |

### 7. Слоты доступности

| ID | Требование | Статус | Тесты |
|---|---|---|---|
| R7.1 | Длительность слота фиксированная — 25 минут | `out of scope` | — |
| R7.2 | Нельзя создать слот в прошлом | `not covered` | — |
| R7.3 | У слота статус `free` или `booked` | `partial` | `api/booking-api`, `e2e/booking-flow` |
| R7.4 | Свой свободный слот можно удалить | `not covered` | — |
| R7.5 | Забронированный слот удалить нельзя | `not covered` | — |

- R7.1: в UI наблюдаемо только время начала; длительность 25 минут в интерфейс как
  вычисленное значение не выводится — black-box доказать нечем.
- R7.3: косвенно через успешную бронь и `confirmed`; явного assert статуса слота нет.
- API-тест `slot_in_past` относится к **бронированию** прошлого слота (R10), а не к
  **созданию** слота в прошлом (R7.2).

| ID | Требование | Статус | Тесты |

| ID | Требование | Статус | Тесты |

## Уровни проверок

| Уровень | Тестов | Что проверяет |
|---|---|---|
| unit | 10 | чистые функции набора: пересечение слотов, валидация пароля, формат времени |
| api | 8 | бизнес-правила брони и регистрации на **локальном мок-сервере** |
| e2e | 14 | пользовательские сценарии в браузере на `aiqa.su/pomidorqa` |
| **всего** | **32** | |

Честная оговорка про пирамиду: unit-уровень проверяет **наш** код в `src/pyramid/`,
а не продукт. API-уровень — учебный мок, а не живой backend PomidorQA. Правила, которые
нужно увидеть глазами пользователя (профиль, каталог, бронь, отмена), закрыты E2E.
